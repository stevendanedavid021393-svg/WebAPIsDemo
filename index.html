APIs Used

API #1: Geolocation API

The Geolocation API asks the browser for the user's current physical location. The call is navigator.geolocation.getCurrentPosition(): it prompts for permission, then returns latitude, longitude, and accuracy. The Get My Location button triggers this call, and the result is displayed above. If permission is denied, the device can't get a fix, or the request times out, the API returns an error instead of a position — this is handled below.

API #2: Web Storage API

The Web Storage API saves key/value data directly in the browser via localStorage, with no server or database required. Data saved this way persists across page reloads and browser restarts until it's cleared. Every location retrieved successfully is saved to localStorage so it's still there the next time the page loads; the Clear Saved Location button removes it.

Error Handling (Details)

Geolocation API — in handleLocateClick()

  • Support check: if (!('geolocation' in navigator)) runs before the API call, to catch browsers or contexts where navigator.geolocation doesn't exist.
  • Error callback: the second argument to getCurrentPosition() handles every GeolocationPositionError code — PERMISSION_DENIED, POSITION_UNAVAILABLE, and TIMEOUT — each with its own message; any other code falls back to a generic one.

Web Storage API — in saveLocation(), loadSavedLocation(), clearSavedLocation()

  • saveLocation(): localStorage.setItem() is wrapped in try/catch to catch a full or disabled storage quota.
  • loadSavedLocation(): both localStorage.getItem() and the JSON.parse() that follows it are wrapped in try/catch, so unavailable storage or corrupted saved data won't crash the page.
  • clearSavedLocation(): localStorage.removeItem() is wrapped in try/catch as well.

Every catch block logs the real error with console.error() and calls setStatus() with a plain-language message, so the user always sees what went wrong instead of a silent failure.
